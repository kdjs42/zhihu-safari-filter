# 过滤规则、性能与自动补充

## v0.3.0 性能改进与自动补充

- 页面变更只处理所属卡片和新增分支；无关 UI 变化不再重读旧帖子。初次进入、修改规则、切换回推荐页才完整扫描。
- 不再每批遍历全部历史状态；移除卡片或整个容器时按移除分支清理。设置面板直接读取维护的计数。
- 默认标题模式不再提取摘要，关闭的分类器不再提取其结构信号；内置规则不再创建超时计时器。
- 不缓存完整帖子 JSON；异步结果通过卡片变更版本和取消信号校验，返回时先处理待通知的 DOM 变更。自定义过滤器仍能获得完整摘要并使用超时/取消机制。

自动补充是独立的 `FeedRefiller`，仅在过滤开启、有内容隐藏、页面可见且本轮过滤完成后工作：

- 有明确的原生“加载更多”按钮时，尝试让当前视口下方保留约两屏内容。
- 只有滚动加载时，等到列表底部距视口底部不超过 200px，再发送一次滚动通知，让网页重新检查加载条件；不修改滚动位置、不临时展开隐藏卡片、不调用私有分页接口。
- 每轮最多发起 5 次辅助触发，至少间隔 1.5 秒；等待新增推荐期间不重复触发。12 秒没有新增推荐就暂停，识别到加载失败或到底标记也暂停。
- 切到后台时不再发起补充（已经由知乎发出的请求无法取消）。暂停后继续滚动至少半屏，或在扩展面板点击“再补充一轮”，可重新尝试；独立开关可关闭整个功能。
- 上限约束的是扩展的辅助触发，知乎自身的自动加载不受本扩展控制。过滤比例高时仍需加载更多原始帖子，因而可能增加流量与页面内存。

**自动补充的适配边界：** 原生按钮与滚动通知两条路径已通过模拟集成测试，但尚未确认当前账号真实首页会接受哪种触发。若知乎仅使用交叉观察器、要求真实滚动事件，或改变加载入口，滚动通知可能无效，此时会超时暂停。不会宣称所有页面都能提前缓存两屏；可在 `ZhihuAdapter.loadControl/requestMore` 中继续适配，无需改动过滤器。

隐藏的卡片仍在知乎页面中，以保证 React 页面及关闭过滤后的恢复行为；本版降低了扩展自身的重复扫描和文本缓存，没有实现页面虚拟化，也不会阻止图片请求。

## 广告与盐选小说的识别边界

- 广告：按 `.TopstoryItem--advertCard`、`.Card.Banner` 和明确为 `1`/`true` 的 `data-za-detail-view-path-is_ad` 标记识别。包含首页推荐广告和首页侧栏 Banner；无标题图片广告也可以隐藏。正文只是提到“广告”不会触发。
- 盐选小说：识别标题、正文之外 UI 上的“盐选小说”“盐选故事”“盐言故事”精确标记，或同名作者；也识别“盐选付费标记 + 虚构创作标记”的组合。不会仅因有盐选购买按钮就过滤，普通盐选知识内容默认保留。
- 无明确标记的软广和伪装成普通回答的小说可能漏过；这些更适合后续通过 LLM 做语义判断。当前为可解释的规则版，不承诺识别所有广告或小说。
- 广告隐藏是页面显示过滤，不是网络请求拦截，不保证节省广告流量或阻止曝光上报。

结构依据：[EasyList China 中的知乎广告选择器](https://github.com/easylist/easylistchina/blob/master/easylistchina.txt)、[知乎增强中的盐选组件识别](https://github.com/XIU2/UserScript/blob/master/Zhihu-Enhanced.user.js)。具体标签组合是本项目的保守启发式，尚未用当前账号的真实推荐样本验证召回率。
